# Bittensor Relics CTO Audit

Date: 2026-08-03

## Executive decision

Bittensor Relics is suitable for a controlled Bittensor testnet beta covering the Forge, fully on-chain media, deterministic indexing, Explore, wallet-owned Relics, transfers, and discovery listings. It is not approved for mainnet, paid marketplace settlement, or claims that a live validator quorum or registered subnet already secures the index.

The most important audit finding was a buyer-loss race in the experimental purchase design. A batch containing a TAO payment and a signed remark is atomic at the runtime-call level, but the runtime does not validate Relic ownership. If ownership changed before the purchase finalized, the payment could succeed while the off-chain indexer rejected the ownership change. Paid buying is therefore disabled until payment and ownership can settle under one enforceable native condition.

## Evidence collected

- All nine indexed Relic media payloads were downloaded from the public API. Every byte length and SHA-256 content hash matched its indexed record.
- Global numbers were ordered deterministically from finalized block and extrinsic position.
- Public pages, evidence routes, and primary APIs returned successfully; unknown routes returned a real 404.
- The production browser emitted no console errors during the audited flows.
- The wallet-unavailable path produced a clear accessible error and did not request a signature.
- Lint, production build, and all 50 protocol/indexer tests passed.
- The production dependency audit reported zero known vulnerabilities.
- Security headers were added for content sniffing, framing, referrer leakage, browser permissions, and frame ancestry.

## Indexing and decentralization

The primary Render indexer is live and is the current source used by the public application. It can reconstruct supported Relics, transfers, listings, and cancellations from finalized Bittensor events. This proves the deterministic indexing model, but it is still one operated service.

The quorum endpoint and network presentation are prototypes. No independently operated replay worker, validator quorum, registered Bittensor subnet, or emission-backed miner network is presently securing production results. The release language must continue to distinguish the live primary index from the proposed decentralized verification network.

## Marketplace safety rule

Listing V1 communicates an owner's signed asking price and expiry for discovery. It does not authorize payment or transfer. The interface must not imply that clicking Buy can safely settle a sale. A paid marketplace may be enabled only after an adversarial test proves the buyer no-loss invariant: TAO payment and canonical Relic ownership must either both finalize or both fail.

## Remaining release gates

1. Deploy at least two independently operated replay indexers and compare deterministic state roots.
2. Define challenges, validator scoring, equivocation handling, and reproducible runtime-upgrade replay.
3. Build the miner optimization queue so users approve the exact final media bytes before spending TAO.
4. Add a native, enforceable payment-plus-ownership settlement primitive before enabling Buy.
5. Complete real transfer, cancellation, stale-listing, and adversarial race tests on testnet.
6. Establish collection authority, moderation, key rotation, and threshold rules.
7. Measure archival cost and set sustainable media limits before any mainnet launch.

## CTO conclusion

The testnet artifact product works: users have created permanent, independently hash-verifiable image Relics tied to finalized alpha burns. The broader network and marketplace vision is not finished. The responsible release posture is to keep forging and discovery on testnet, describe the current trust model precisely, and refuse paid settlement until the chain can enforce the complete exchange.
